# `final_gpu_stability_test.sh` — 8× MI300X / Kimi-K2.6 stability validation

One script, one command. It localizes GPU hangs to **hardware · ROCm/HSA · AITER kernels · RCCL/XGMI · vLLM config**, and writes a full evidence bundle + PASS/FAIL report.

## Run it

```bash
sudo bash final_gpu_stability_test.sh                    # SAFE suite, smoke mode (default)
sudo bash final_gpu_stability_test.sh --mode stability   # SAFE suite, long/sustained mode
sudo bash final_gpu_stability_test.sh --include-unsafe-matrix   # also run the HSA-disabled (crash-prone) rows
```

- **Safe by default.** The HSA-override-**disabled** configuration (the one previously tied to hangs) is OFF unless you pass `--include-unsafe-matrix`, which then prints a warning and requires you to type `yes-run-unsafe`.
- `sudo` is needed for `dmesg`/sysfs/`amd-smi`.
- Nothing is reset, reloaded, rebooted, or reflashed. The script only stops/removes containers it started (names prefixed `gpu_stab_<timestamp>`).

## What it does (stages)

| Stage | Check |
|---|---|
| Environment | GPUs, kernel, driver, docker, image id, in-container torch/vLLM versions |
| Pre-flight | reuses your existing health script if found (`PREFLIGHT_SCRIPT=…`), else an inline idle+dmesg gate; **aborts if the cluster isn't clean** |
| Compute/memory | in-container PyTorch matmul + large alloc on all 8 GPUs |
| RCCL/XGMI | `all_reduce_perf` if present, else a portable `torch.distributed` all-reduce across 8 ranks; + XGMI link snapshot |
| vLLM matrix | Baseline (HSA on, AITER on, sustained) · Kernel-comparison (HSA on, AITER off) · *[unsafe]* Architecture-check (HSA off) · *[unsafe]* AITER-isolation (HSA off, AITER off) |
| Inference | real requests to `/v1/completions` after `/health` is ready — success rate, latency, timeouts |
| Report | PASS/FAIL/INCONCLUSIVE/SKIPPED, kernel faults, root-cause heuristic, recommended config |

Health is monitored during **every** stage (dmesg fault-delta + telemetry). On a GPU fault or hang the script **stops** — it will not stress an unhealthy cluster — and leaves the GPU as-is for inspection.

## Test matrix

| Test | HSA override | AITER | Workload | Safe? |
|---|---|---|---|---|
| Baseline | enabled (9.4.2) | on | load + sustained inference | ✅ |
| Kernel comparison | enabled | off | short inference | ✅ |
| Architecture check | **disabled** | on | short init | ⚠️ opt-in |
| AITER isolation | **disabled** | off | short inference | ⚠️ opt-in |
| Compute/memory | n/a | n/a | 8-GPU compute+alloc | ✅ |
| Communication | n/a | n/a | 8-GPU RCCL/XGMI | ✅ |

Each config runs **sequentially**, never concurrently. Disabling AITER is **verified** against the server log (all-reduce backends + IR op priority), not assumed.

## Output

```
gpu_stability_results/<YYYY-MM-DD_HHMMSS>/
├── environment.txt        final_report.md       ← human summary + root cause
├── preflight.log          test_results.json     ← machine-readable
├── gpu_telemetry.csv       inference_metrics.json
├── kernel_logs.txt        run.log
├── rccl_test.log          vllm_baseline.log / vllm_aiter_off.log / vllm_hsa_off.log …
```

`final_report.md` and `test_results.json` are **generated by the run** (not pre-filled). Partial results are saved even if a stage crashes or times out.

## Reading the result

- **Baseline PASS + Architecture-check FAIL** (unsafe run) → strong evidence the hangs come from **removing `HSA_OVERRIDE_GFX_VERSION=9.4.2`**; keep it set. The report states this with a confidence level.
- **All safe stages PASS** → the config is serviceable *for this finite test* (the report will not claim "crash-free").
- **compute/RCCL FAIL** → points at hardware / XGMI rather than vLLM config.
- `INCONCLUSIVE`/`SKIPPED` → a tool was missing or a marker wasn't seen; the report says which — these never silently pass.

## ⚠️ Verify before you run (these were inferred, not taken from your serve.sh)

1. **Docker flags** — `DOCKER_DEVICE_ARGS`/`EXTRA_DOCKER_ARGS` match the logged `--device /dev/kfd --device /dev/dri --group-add video` plus `--ipc=host --shm-size=16g` (needed for TP shared memory). If your production `serve.sh` uses different flags or volume mounts, set them via these env vars.
2. **Pre-flight script** — set `PREFLIGHT_SCRIPT=/path/to/your/healthcheck.sh` to reuse it; otherwise the inline gate (from `kernel_health_checks.md`) is used.
3. **vLLM flags** — the core flags are standard vLLM 0.30.0; attention backend is passed as `VLLM_ATTENTION_BACKEND` (env), not a CLI flag. Confirm against your serve.sh.
4. **Guardrail** — `MAX_NUM_SEQS` defaults to 256 and warns if raised above it.

## Rough runtime
- **smoke:** ~15–30 min (dominated by two Kimi-K2.6 TP8 model loads; disk-bound).
- **stability:** ~50–75 min (30 min sustained inference + longer compute).
- **+ unsafe matrix:** add ~15–25 min (two more loads; a hang row can burn up to its timeout).
